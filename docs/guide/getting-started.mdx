# Installation

Run zeropaste with Docker Compose or as a single binary, then register the owner account and create your first share.

zeropaste is one Go program that keeps ciphertext files on disk and serves your browser - no database, no cache, no build step, one container or one binary is all it needs.

:::caution
Passkeys need a domain.

Browsers only allow WebAuthn on HTTPS pages, or on `localhost` while you try things out. Plan for a domain such as `paste.example.com` and put a TLS-capable reverse proxy in front of zeropaste - the app itself stays plain HTTP on purpose. See [reverse proxy](/guide/reverse-proxy).
:::

## Install

### Docker Compose

Download the compose file from the repository (every knob is a commented line, so the file is safe to commit with them untouched):

```bash
curl -O https://raw.githubusercontent.com/2TAP2B/zeropaste/main/compose.yaml
```

Uncomment exactly what your instance needs - never commit a real key:

```yaml
services:
  zeropaste:
    image: ghcr.io/2tap2b/zeropaste:latest
    ports:
      - "8080:8080"
    volumes:
      - paste-data:/data
    restart: unless-stopped
    # environment:
    #   - CREATE_KEY=change-me          # passphrase gate in front of pasting
    #   - LOCKED=true                   # members only - passkey sign-in to paste
    #   - MAX_TTL_DAYS=7                # ttl ceiling, 1..366
    #   - MAX_SHARES_PER_ACCOUNT=50     # 0 = unlimited
    #   - MAX_UPLOAD=104857600          # total ciphertext per bundle (bytes)
    #   - CHUNK=8388608                 # per-request chunk size (bytes)
    #   - PUBLIC_PASTES=false           # drop the plaintext public-paste slider
    #   - USER_ACCOUNTS=false           # disable passkey accounts entirely
    #   - USER_REGISTRATION=false       # closes sign-up after the first account
    #   - REG_OPEN=false                # registration only via invite links

volumes:
  paste-data:
```

Start it:

```bash
docker compose up -d
```

The image is published on GHCR as `ghcr.io/2tap2b/zeropaste`; it is about 9 MB and carries the whole frontend, embedded.

### Docker

A single command gets you a fully open instance:

```bash
docker run -d --name zeropaste -p 8080:8080 -v paste-data:/data ghcr.io/2tap2b/zeropaste:latest
```

Open `http://localhost:8080` and share - that is the whole deployment.

### From source

Building needs Go 1.26 or newer:

```bash
git clone https://github.com/2TAP2B/zeropaste && cd zeropaste
go build -trimpath -ldflags="-s -w" -o zeropaste .
./zeropaste -addr 127.0.0.1:8080 -data ./data
```

Flags: `-addr` (listen address, default `127.0.0.1:8080`) and `-data` (state directory, default `data`). Everything else is environment or the [admin config](/guide/configuration). Run it as a service with systemd or your platform's equivalent.

### NixOS

The flake ships a hardened module (no external flake inputs):

```nix
# your flake.nix
inputs.zeropaste.url = "github:2tap2b/zeropaste";

# inside nixosConfigurations.<host>
imports = [ inputs.zeropaste.nixosModules.zeropaste ];
services.zeropaste = {
  enable = true;
  listenAddress = "127.0.0.1:8080"; # loopback default; your reverse proxy does TLS
};
```

The module runs with a `DynamicUser`, keeps state in `/var/lib/zeropaste` and sandbox-hardenes the unit. Standalone: `nix run github:2tap2b/zeropaste`.

## Register the owner account

Open the site and click the account button to create an account with a passkey.

- The **first registered account owns the instance** - it gets the admin flag, the config tab, [invite links](/guide/accounts) and the admin surface. Hand yesterday's env knobs to the UI: after the first save, the on-file config wins over the compose env, and `Save + reboot` applies it.
- Everyone after that registers non-admin until you promote them in the config card.
- Anonymous pasting stays available (and is the default) unless you lock the instance down.

## Create your first share

1. Paste anything into the compose card - or drop files, or hit Ctrl+V with an image on the clipboard.
2. Pick a ttl, optionally flip `burn after reading`, hit **Encrypt & share**.
3. The share link carries the decryption key in the fragment (`#...`) - send it to anyone; the key never leaves the URL bar and is stripped from it after decrypt.

The [shares guide](/guide/shares) covers passphrases, burn-after-reading and the public lane; [files and images](/guide/files) covers bundles and chunked uploads.

## What leaves the box

Nothing. zeropaste makes **zero outgoing requests** - no update checks, no analytics, no CDN, no remote fonts or icons. Once running, the instance is inert:

- all assets (including syntax highlighting and QR rendering) are embedded in the binary;
- the service worker caches only the static shell - paste traffic (`/api/*`) always hits your instance and is never cached;
- the process never logs request IPs or content; there are no plaintext values on disk to export.

That makes air-gapped deployments a non-story: nothing to disable.

## Upgrading

- **Compose:** `docker compose pull && docker compose up -d`. State lives in the `paste-data` volume; upgrades carry nothing but the binary.
- **Source:** pull and rebuild; the data directory format is forward-compatible within a release line.
- **After the first config save:** the file layer beats compose env, so remove an undone env override at the source too - the config card tells you exactly what fires on the next boot (`restartNeeded`).

Reader links keep working across upgrades: links are self-contained (`/p/<id>#<key>`), and keys never exist on the server to migrate in the first place.
