# security posture

The product is a threat model made code. This page states what zeropaste protects, what it deliberately does not, and where the ceilings are.

## what the server cannot know

- **content** - AES-256-GCM ciphertext only; keys live in URL fragments or user heads (or nowhere, for plaintext lanes you opted into).
- **filenames** in bundles - the manifest is encrypted with the share key.
- **passphrases** - the server stores a random salt; the key derivation happens in the browser (PBKDF2-HMAC-SHA256, 600k iterations).
- **who you are** - no request logs, no IP storage, anonymous by default; the rate limiter counts per window in memory and forgets.

## trust boundaries

| layer | guarantee |
| --- | --- |
| transport | app serves HTTP; TLS + HSTS are the proxy's job |
| validation | every boundary: ttl shape, length caps, strict base64url, `validID` charset (the sole path-traversal gate), `MaxBytesReader` everywhere |
| CSRF | JSON/bearer bodies on every state-changing endpoint, no CORS headers ever, and Go's cross-origin protection: browsers' non-GET requests from another origin - including a sibling subdomain - are refused (`Sec-Fetch-Site` / `Origin`) |
| cookies | HttpOnly, SameSite=Lax, `Secure` on HTTPS; bounded MaxAge; HMAC-SHA256-signed with a 32-byte secret (`data/.session.key`, or `SESSION_SECRET` - at least 32 bytes, else the server refuses to start) |
| rate limits | per client: the connecting address, or - only when the peer is on loopback/a private network (your proxy) - the last `X-Forwarded-For` entry; IPv6 per `/64`. A public peer cannot pick its own bucket |
| abuse floors | creates and uploads stop with `507` before the data volume drops under 512 MiB free; upload chunks stream to disk; pending passkey ceremonies expire after 2 minutes and are capped |
| headers | `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, strict CSP with `blob:` only for decrypted previews |

## supply chain

- one direct Go module (go-webauthn); everything else is stdlib.
- **Dependabot** watches every ecosystem in the repo: Go modules (weekly, grouped), the Docker base images (daily - a `golang` patch release is usually a security release), GitHub Actions, the docs site's npm packages and the Nix flake. Version bumps wait out a short cooldown; security updates open immediately.
- **CI** (`ci.yml`) runs on every push and pull request - the full test/typecheck gate, the bundle-freshness check, the Nix package, the NixOS module booted in a VM, and the container smoke-tested with the compose hardening - and **daily `govulncheck`** against *both* shipped Go toolchains (the Docker builder and the Nix package), so a newly published Go advisory fails CI even when nothing in the repo moved.
- base images are pinned by tag **and digest**; every action is pinned to a full commit SHA; workflows run with least-privilege tokens.
- release images carry an SBOM and SLSA provenance attestation.
- shipped toolchains track the patched Go release (currently Go 1.26.11: CVE-2026-97054 / GO-2026-6859 and the earlier eMudhra intermediate distrust, CVE-2026-111943).

## the deliberate ceilings

Marked `// ponytail:` in the code - weaker-but-fine behavior for a friend-group tool, preserved on purpose:

- two racing burn-after-reading readers can both succeed (read-then-delete is not atomic).
- pending webauthn ceremonies live in memory (2 min) - a restart drops them; multi-instance deployments share nothing.
- a heavily renamed legacy identity can win the oldest-file admin migration; the boot log names the pick.
- bundle encryption is in-memory: ~2 GiB is the practical bundle ceiling.
- sessions are stateless signed cookies: **logout clears the cookie in that browser only**; a copied cookie stays valid until it expires (30 days). Rotating `SESSION_SECRET` (or deleting `data/.session.key`) signs everyone out.
- whoever holds the link to an **encrypted** paste can delete it (the passphrase burn needs that client-side DELETE); public pastes are owner-only.
- peers on loopback/private networks are trusted to name the client via `X-Forwarded-For`; on a LAN without a proxy, a LAN client can therefore pick its own rate-limit bucket.
- the free-space floor is a fixed 512 MiB, measured with `statfs` - the server builds on Linux, macOS and FreeBSD (the shipped images and packages are Linux).

## what the app embeds

Everything the frontend needs ships inside the binary: the UI, syntax highlighting, QR codes, icons. **No CDN calls from the frontend** - a self-hosted instance never talks to third parties when you paste.

## reporting

Report vulnerabilities privately: [Security → Report a vulnerability](https://github.com/2TAP2B/zeropaste/security/advisories/new) on GitHub (see `SECURITY.md`). Please don't open public issues for anything exploitable.
