# reverse shares

A normal share sends something from you to a friend. A **reverse share** flips it: you set up a drop link, friends upload through it, and the arrivals land in your dashboard.

## the model

1. On the dashboard's **reverse** tab, fill in the form: a slug (`my-inbox`), when the link expires, a max size in MB, and optionally a passphrase.
2. The result is a drop link: `https://your.site/r/my-inbox#<key>` - the uplink key rides the fragment, exactly like a paste.
3. Friends open the link and upload files; every upload is an ordinary encrypted share created through the standard pipeline - the server never sees the key, so it cannot read arrivals.
4. Your dashboard lists each inbox with file count, total size, expiry and cap; expand a row for the drop link itself and the arrivals - links that decrypt locally in your browser (file names stay inside the encrypted bundles).

## passphrase uplinks

Optionally protect an inbox with a passphrase instead of a fragment key: senders run a small unlock card, and their uploads re-open later through the ordinary passphrase flow - no fragment key needs to travel at all.

## rules

- slugs are globally unique (`3-32` chars, `a-z0-9_-`);
- the sender side (`GET /api/rshare/<slug>`, upload, register) is public and rate limited; the sender only ever learns the size cap and expiry - never your inventory;
- deleting an inbox **deletes every registered paste with it** - you hold the uplink key, so contents without it would be dead weight;
- expired inboxes vanish with their contents.

## recovery of a lost key

If your browser loses the stashed fragment key for an inbox, its row carries a *key missing* chip and the expanded detail shows a repair field: paste the original drop link back into this browser and the key re-stashes. Opening your own intact drop link in this browser heals the row too.

The drop-link page only ever **fills a missing key** - it never replaces one this browser already holds, so a crafted `/r/<your-slug>#<other-key>` link sent to you cannot swap your key. If a row's arrivals won't open because you recreated the slug on another device, use the same field (it reads *Replace* when a key is present) with the current drop link.

Recreating the uplink is **not** a recovery - a fresh key orphans every upload already sent with the old one.
