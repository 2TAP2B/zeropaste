# configuration

Three layers, resolved once at boot: **config file > process env > built-in default**. The admin UI writes the file (`data/config.json`); env stays useful for compose deployments and first boot.

## the admin config

The dashboard's config tab manages the whole instance in two cards:

- **instance settings** - the knobs below. Edits are a draft: a sticky save bar at the bottom of the card shows *unsaved changes* (with **Discard**), and after a save it reads *saved - reboot to apply* with a **Reboot now** button. A save lands in `data/config.json` (mode 0600) and goes live after the reboot (a graceful drain, then the deployment's restart policy brings the process back with the new layer). Knobs are boot-frozen on purpose: a mid-life chunk shrink would strand in-flight uploads.
- **people** - admin rights and invite links. These apply immediately, no save needed ([see accounts](/guide/accounts)).

### who can paste (exclusive choice)

| tile (API value) | effect |
| --- | --- |
| anyone (`open`) | visitors paste right away |
| gate passphrase (`passphrase`) | the compose lane sits behind a shared passphrase (the create-gate); the key is stored server-side as a secret, shown only as *set* |
| members only (`members`) | pasting needs a passkey sign-in; reads stay open |

The passphrase mode requires a key: picking it reveals the gate passphrase field (the placeholder says whether a key is already stored - leave it empty to keep that one). Switching to another mode while a key is stored offers a **forget the stored gate passphrase** switch that removes it from the file on save. The running process enforces exactly one gate.

### sign-up (exclusive choice)

| tile (API value) | effect |
| --- | --- |
| open (`open`) | anyone can register |
| first account only (`first`) | closes after the first account (first-user bootstrap) |
| invite links only (`invite`) | closed; [invite links](/guide/accounts) unlock registration |

### allow plaintext public pastes

Switch. Off (the default is on) drops the plaintext-lane slider from compose; public creation is always account-only regardless.

### limits

| knob | default | range |
| --- | --- | --- |
| max ttl | 30 days | 1..366 days |
| shares per account | 0 = unlimited | 0..100000 |
| max upload | 100 MB | 1 MB..64 GB |
| chunk size | 8 MB | 0.0625..64 MB |

The UI shows sizes in MB (MiB) while the API and the file store bytes; an untouched size field sends its exact stored byte count back, so the display rounding never changes a value. Cross-checked: chunk ≤ max upload, enforced on the merged next-boot pair.

## environment variables

Env vars keep working as first-boot layers - after one admin save the file owns a knob until the file is deleted.

| env | default | meaning |
| --- | --- | --- |
| `CREATE_KEY` | unset | enables the passphrase gate (its presence is the switch) |
| `LOCKED` | `false` | members-only compose lane |
| `PASTE_ACCESS` | - | file knob (`open` / `passphrase` / `members`) beats the two above |
| `REG_OPEN` | `true` | `false` closes registration to invite links |
| `USER_REGISTRATION` | `true` | `false` closes sign-up after the first account |
| `REGISTRATION` | - | file knob (`open` / `first` / `invite`) beats the two above |
| `PUBLIC_PASTES` | `true` | plaintext public-paste lane |
| `USER_ACCOUNTS` | `true` | `false` disables the entire identity subsystem (config tab included - it must not hide its own door) |
| `MAX_TTL_DAYS` | `30` | ttl ceiling, 1..366 |
| `MAX_SHARES_PER_ACCOUNT` | `0` | per-identity active share cap |
| `MAX_UPLOAD` | `104857600` | total ciphertext per bundle |
| `CHUNK` | `8388608` | per-request chunk |
| `SESSION_SECRET` | auto | HMAC secret for session cookies (else `data/.session.key`, auto-generated) |
| `ADMIN_ID` | auto | names the admin identity id explicitly for the boot migration |

## precedence details

- A config file with legacy fields (`locked`, `createKey`, `regOpen`, `userRegistration`) migrates to the exclusive modes automatically - each legacy field still beats its own env, and the stricter mode wins the choice.
- The running process never adopts a saved knob live: **Save + reboot** is the application path, `restartNeeded` in the view tells you when a draft differs from what runs.
- A corrupt config file fails the boot loudly - it is UI-written, so silence would be a bug.
