# AGENTS.md - zeropaste

Instructions for agents working on this repository. If you rebuild this project from scratch, follow this document exactly; it is a complete specification of every deliberate decision.

## 1. What this project is

**zeropaste** - a self-hosted, zero-knowledge paste-sharing service for a small friend group. Users paste text, passwords, or code snippets; the browser encrypts them (AES-256-GCM) and the server stores only ciphertext. Sharing works via a link whose URL fragment (`#...`) carries the decryption key, or - for passphrase-protected pastes - via a link plus a separately shared passphrase.

Hard constraints (do not violate, do not "improve"):

- **Single Go binary.** One third-party Go module (go-webauthn for passkeys) - everything else is stdlib; no web framework, no router lib, no DB driver.
- **Zero-knowledge.** Keys are generated and used exclusively in the browser (WebCrypto). The server never sees plaintext, keys, or passphrases. No CDN calls from the frontend; everything (including syntax highlighting) is embedded in the binary.
- **Anonymous by default; optional passkey accounts.** Anonymous pastes keep the original link-is-the-capability design: no cookies, no sessions, no per-request logging. The shipped phase-2 identity system (passkeys) exists ONLY for the private active-shares dashboard: HMAC-signed `zp.session` cookie (HttpOnly, SameSite=Lax), identity names + public-key material in `data/identities/`, ownership rows in `data/shares/` - never paste content or keys. The whole subsystem can be disabled with `USER_ACCOUNTS=false` (see §5). (Exception: the optional create-gate below - a single site passphrase in front of `POST /api/paste` via env `CREATE_KEY`; it is not a user-account system.)
- **English UI only.**
- Allowed Go version: 1.26+ (go.mod directive `go 1.26.0`; built and verified on 1.26.x).

Out of scope by design (an agent must not add these): paste editing, comments, per-language syntax selection, a database.

**Spec revision v0.3 (user approved):** file uploads ARE in scope now (phase-1); passkey accounts shipped with phase-2. The zero-knowledge crypto contract (§2) is untouched: the server only ever stores ciphertext.

## 2. Crypto contract (non-negotiable)

- Encryption: **AES-256-GCM** via browser WebCrypto.
- Random-key flow (default): 32 random bytes → raw key. Payload sent to server: `base64url(iv [12 bytes] ‖ ciphertext)`.
- Passphrase flow (optional): 16 random salt bytes (base64url, sent to server) + **PBKDF2-HMAC-SHA256, 600,000 iterations** (OWASP figure) → derived AES-256 key. The passphrase never leaves the browser; the server stores only the salt.
- Random-key pastes: key in the **URL fragment** (`/p/<id>#<keyB64>`) - fragments are never sent to servers, logs, or proxies. The reader strips it via `history.replaceState` after decryption.
- Passphrase-protected links contain **no** fragment.

**Scope amendment (v0.10.0, user approved):** the contract above applies to non-public pastes. A signed-in creator may flip the compose slider `public paste` and send a TEXT paste as plaintext: the server stores and serves exactly what was sent, the link is a bare `/p/<id>` with no fragment, no key exists anywhere. File bundles ride the same plaintext lane (v0.10.2): identical envelope framing `u32le ‖ manifest ‖ files ‖ thumbs` but with NO IVs and raw bytes - the manifest starts at offset 4. No listing/SEO surface. Default stays zero-knowledge; the choice is explicit per paste and per instance (`PUBLIC_PASTES`, accounts-only creation - see §4).

## 4. API contract

Base: all routes carry security headers via `secure()` middleware. Errors are JSON `{"error": "<generic message>"}` - never internal details.

**Hardening posture (audit trail, see the security-and-hardening skill):** validation at every boundary (ttl parse, length caps, strict base64url, `validID` charset = the sole path gate, `MaxBytesReader` everywhere); CSRF blocked by construction (state-changing endpoints require JSON/bearer content, cross-site preflight fails - no CORS headers are ever emitted); cookies HttpOnly+SameSite=Lax+`Secure` when the request is HTTPS (direct TLS or `X-Forwarded-Proto`) with bounded MaxAge; secrets only from env/`.session.key` (gitignored `data/`); no request logs, no IPs; retention = TTL janitor. Supply chain: `govulncheck ./...` runs in the release gate as the recorded audit - findings are triaged against reachability (GO-2026-5932, x/crypto/openpgp, is module-level only and not reachable).

### `POST /api/paste` (rate limited: 30/min/IP, then HTTP 429)

Request JSON:

```json
{"data": "<base64url(iv‖ct)>", "salt": "<base64url or ''>", "ttl": "1d", "hl": true, "burn": false}
```

Validation, in order, all failures produce 400:

- Body capped by `http.MaxBytesReader` at 256 KiB; JSON decode failure → 400.
- `ttl` parsed by `parseTTL`: lowercase, spaces stripped, `<number><unit>` with unit in {m, min, mins, minute, minutes, h, hr, hrs, hour, hours, d, day, days}. Must equal 1 minute … 30 days (both inclusive); 30 days is a hard ceiling. Compound durations like `1h30m` are intentionally unsupported.
- `data`: strict base64url decode, decoded length ≥ 28 (12 IV + 16 GCM tag) and ≤ 64 KiB (`maxData`).
- `salt` (if non-empty): base64url decode to 8–32 bytes.
- **Public lane** (`"public": true` in the request): checked BEFORE the base64url branch - disabled instance → 400 generic; `owns.sess.identFrom(r) == nil` → 403 (accounts-only); `salt` non-empty → 400 (contradiction); `slug` (optional, PUBLIC-ONLY - a slug on an encrypted paste → 400) must pass `validID` (8–16, `[A-Za-z0-9_-]` - it becomes the `/p/` path segment, so it satisfies the very gate that validates those paths) else 400; claimed with `os.O_CREATE|os.O_EXCL` so a lost race → 409 "slug already taken", never a silent overwrite; then instead of base64url validation: `data` must be non-empty and ≤ `maxData` bytes of raw UTF-8 (anything the client sent is stored verbatim). Meta gains `"public":true`.

Success: 200 `{"id": "<11-char base64url of 8 random bytes>"}` - or the custom slug when one was claimed. File written as `<dir>/<id>.json`, mode 0600, data dir created 0700. `newID(dir)` retries on the (astronomically unlikely) collision **against the data dir** - a previous version checked `./` and was wrong; do not regress.

**Feature env switches** (all optional; unset = defaults below): `PUBLIC_PASTES` (default `true`; `false` drops the compose slider, `POST public:true` → 400, and `/api/gate` reports `"public":false`; dynamic read like `REG_OPEN`; public creation is ALWAYS accounts-only - `USER_ACCOUNTS=false` kills the feature entirely regardless of this knob), `USER_ACCOUNTS` (default `true`; `false` drops the whole identity subsystem - ceremony routes unregister server-side, `/api/me` stays up carrying `"accounts":false`, the client hides the account button and the dash anon card drops its sign-in button; POSTs to the dropped routes fall through the `GET /` catch-all to 405, no identity-shaped answer exists), `USER_REGISTRATION` (default `true`; `false` = first-user bootstrap: registration works until one identity file exists, then behaves like `REG_OPEN=false` - the existing static switch keeps precedence), `MAX_TTL_DAYS` (default `30`, 1..366: `parseTTL` ceiling for text and upload pastes; `uploadFinish` re-checks the cached init TTL so a crafted manifest cannot outlive it), `MAX_SHARES_PER_ACCOUNT` (default `0` = unlimited; `mayCreate` counts non-expired ownership rows and `POST /api/paste` plus `uploadFinish` answer `403 share limit reached` beyond it).

### File uploads (chunked, resumable) - build on `/api/uploads`

Config via env at startup: `MAX_UPLOAD` (default `104857600` = 100 MiB, 1 MiB..64 GiB) total ciphertext per share; `CHUNK` (default `8388608` = 8 MiB, 64 KiB..64 MiB) per PUT and per range GET; `MAX_UPLOAD < CHUNK` is a fatal misconfig. Values are plain byte integers.

- `POST /api/uploads` `{len, ttl, salt, burn, public, slug}` → `{"id", "chunkSize": CHUNK, "chunks": ceil(len/CHUNK)}`. Body capped 1 KiB. Same ttl/salt validation as `POST /api/paste` (ttl shape only here; expiry computed at finish). **Public lane** (`public: true`, v0.10.2): checked before the salt decode - disabled instance → 400; `owns.sess.identFrom(r) == nil` → 403 (accounts-only); `salt` non-empty → 400; `slug` (optional, PUBLIC-ONLY) must pass `validID` else 400 - stored on the session manifest (`{len, ttl, salt, burn, created, public, slug}`). Creates `data/uploads/<id>/upload.json` 0600, dirs 0700. Id = 8 random bytes b64url, collision-checked against the uploads dir.
- `PUT /api/uploads/{id}/{n}` - raw ciphertext chunk `n` (0-based). `validID` gates `{id}`; `n` strict int `0..chunks-1`; body `MaxBytesReader` at CHUNK+1, `1..CHUNK` bytes required. Overwrite = resume. **NOT rate limited** (a 2 GiB share is ~250 PUTs; body caps + temp quotas carry the protection). Behind the create-gate when enabled.
- `DELETE /api/uploads/{id}` - `os.RemoveAll(session)`, idempotent 200 `{"ok": true}`. Public (abort must always work).
- `POST /api/uploads/{id}/finish` - rate limited + gated like a paste create. Public sessions re-check `publicPastesOn()` + the session (mirror of the ttl re-check). Verifies every `n.part` exists with exact sizes (full chunks = CHUNK, last = len-(chunks-1)*CHUNK), joins to `<dir>/<finalID>.blob` 0600, writes meta `<dir>/<finalID>.json` (`{len, salt, burn, expires, public}`, no `data`), removes the session dir. **Slugged sessions** finish under the custom name: the blob is claimed with `O_EXCL` on the final name (a taken slug → 409 "slug already taken", never a clobbered paste - incl. the slug held by a text paste: the blob claim fails first or the meta claim removes the just-created blob), the meta is claimed `O_EXCL` last, and the session dir keeps a `finished` TOMBSTONE (chunk PUTs to it → 404; the sweep reaps it by age) so a repeat finish still answers `200 {"id": slug}` idempotently. Incomplete/off-size → 400, parts kept for retry, partial blob removed. Double finish → 200 idempotent.
- `GET /api/paste/{id}/blob?offset=N` - ciphertext ranges (`no-store`, `application/octet-stream`), max CHUNK bytes from offset; off-range offset → 400; expired → 404 + file removed. Reader paginates 0..len.
- Meta read for a bundle (`len > 0`) with `burn && salt==""`: expiry flips to `now-1+30s` grace window (var `burnWindowSec`) so the legitimate reader can finish the range downloads; janitor reaps both `<id>.json` and `<id>.blob` when expired. Text pastes keep exact read-then-delete. **`DELETE /api/paste/{id}` removes `.blob` too** (bundle dies whole, burn flag or not).
- Janitor (`sweep`, shared with tests): also removes `uploads/<dir>` sessions whose manifest is missing or `created` older than 2h.

### Create-gate (optional auth in front of POST)

- Enabled when env `CREATE_KEY` is non-empty at startup (its presence *is* the switch - no separate boolean). Disabled entirely when unset/empty.
- `POST /api/paste` then requires header `Authorization: Bearer <CREATE_KEY>`, compared with `subtle.ConstantTimeCompare` (`authGate`). Failure → 401 generic error. Tested at 30/min/IP by the same limiter.
- Everything else stays public behind the gate: reads, DELETE (burn pastes need it after decrypt), `/`, `/p/`, `/assets/`, `/healthz`.
- **Create-gate UX is a full-screen pre-screen**, not a field in the compose card: with the gate enabled, the client renders a bare unlock card (`#gate`, passphrase input + Unlock button) *before* any app view. Verification runs against `GET /api/gate` (→ `{"enabled": bool, "maxTtlDays": int, "public": bool}` - the TTL ceiling and the public-paste capability ride along so the compose card can adapt; same response whether the gate is on or off) and `POST /api/gate` (Bearer candidate → 204 or 401, rate limited). On 204 the passphrase is kept in `sessionStorage` key `zp.siteKey` (per tab, never localStorage, never a cookie) and future sends carry it as `Authorization: Bearer`. A 401 from a paste create drops the user back to the gate screen (stale key). Reader views (`/p/…`) never show the gate.
- The create flow needs no UI changes when the gate is disabled: `GET /api/gate` says `enabled:false`, the compose card renders directly.

### Reverse shares (0.8.0): dash-set drop links that collect friend uploads

- Storage: `data/inboxes/<slug>.json` 0600 - `{slug, owner (identity id), maxSize, expires, created, uploads[]}` pure metadata (ids, sizes, times). Contents are ordinary encrypted pastes/bundles created through the STANDARD create/upload endpoints with the uplink key riding the `/r/<slug>#<keyB64>` fragment, so the zero-knowledge contract holds unchanged (the server never sees the key).
- Owner endpoints (session-gated): `POST /api/rshare` `{slug, ttl, maxSize}` creates an inbox - slug `validSlug` (3–32, `a-z0-9_-`), **globally** unique across owners (409 free-check), ttl clamped through `MAX_TTL_DAYS`, maxSize 1..`MAX_BLOB`; creation counts against `MAX_SHARES_PER_ACCOUNT` (inboxes owned, not just pastes). `GET /api/rshares` lists the owner's live inbox rows (+ per-item ids/sizes). `DELETE /api/rshare/{slug}` removes the inbox AND every registered paste (files + blobs) - the owner holds the uplink key and delete-with-contents is the contract.
- Sender endpoints (public, rate limited): `GET /api/rshare/{slug}` → `{maxSize, expires}` only (no owner/inventory leak). `POST /api/rshare/{slug}/in` `{id}` registers an existing paste: 404 when unknown/expired, 403 when the paste `Len` exceeds the inbox cap, idempotent on re-register. Sender routes stay registered even with `USER_ACCOUNTS=false` so live uplinks keep working.
- Janitor: expired inboxes sweep straight out (uplink dies with them). `GET /r/` serves the index via `serveIndex` (slug validated `validSlug`, else 404).
- Setup with an OPTIONAL passphrase: the client derives the uplink AES key from passphrase + fresh 16-byte salt (PBKDF2, 600k) locally, seals a verifier (`seal(key, "zeropaste-rshare")`), and posts `{salt, check}` with the create - server stores both on the inbox, validates the pair (salt 8–32; check ≥ 12+16 bytes; check-without-salt rejected) and returns them in the public meta. Passphrase uplinks use a BARE `/r/<slug>` link (no fragment ever) - senders run the `#runlock` unlock card (`deriveKey` → `open_(check)` → "Wrong passphrase." mirror of the paste unlock) and upload with `UploadOpts.preKey` + `preSalt` (built into every uploaded paste meta so arrivals re-open through the STANDARD /p/<id> passphrase flow - no owner fragment needed). Fragment mode (no passphrase) keeps stashed keys as before; dash rows ignore stale fragment stashes for pass-mode slugs. **Fragment-key recovery (client-local, no server changes):** the reverse view re-stashes the key on EVERY browser that opens an intact link (`stashForCreate("rv:"+slug)` in the fragment branch), and a dash row with a missing key renders a repair row - paste the original drop link (or just its fragment) back into this browser; the client validates the sender-side shape rule `[A-Za-z0-9_-]{10,}`, re-stashes, re-renders. Never treat "recreate the uplink" as recovery for lost keys: a fresh key orphans uploads already sent with the old link (they arrive undecryptable); deleting the inbox (with contents) is the only destructive path.

### Identity (phase 2): passkeys via go-webauthn (first third-party dep)
- Storage stays file-shaped: `data/identities/<id>.json` (`{id, name, creds[]}` - creds are the lib's `webauthn.Credential` JSON). Sessions are HMAC-signed cookies (`zp.session`: `b64url({sub,exp}).b64url(sig)`), HttpOnly SameSite=Lax, 30 day TTL. Secret: `data/.session.key` (auto-generated 32 B, 0600) or env `SESSION_SECRET`.
- `GET /api/me` → `{name, open, passkeys[]}` (credential ids b64url of the signed-in identity; `[]` anonymous; `open = registrationOpen()`; anonymous name stays empty). `POST /api/identity/{register,login}/begin|finish` (rate limited), `POST /api/identity/logout` clears the cookie. `REG_OPEN` env (default true; plain bool): false → fresh registrations 403 (sign-ins and attach-to-session always open). Pending registration identities live in the ceremony's in-memory `tokens` map - the identity file is written only when `finish` succeeds (previous "identity missing" bug: finish used to load a file that doesn't exist for fresh registrations). The client surfaces `window.isSecureContext` - non-localhost HTTP gets a disabled pane + hint (WebAuthn rejects IP/HTTP rpId).
- RP config derives from the request per ceremony: `RPID = host (no port)`; RPOrigins allow BOTH schemes of the host (proxies may skip X-Forwarded-Proto; the RPID pin carries the ceremony). Session challenge state lives **in-memory** (`ceremony` map, 2 min) - a restart drops pending ceremonies; that is the ponytail ceiling for multi-instance deployments. IP-literal hosts can never hold passkeys (go-webauthn rejects IP RP IDs): `isIPHost` begin-guards return 400 "passkeys are not available on an IP address" and the client disables the pane with the matching hint (`localhost` domains are fine; 127.0.0.1 counts as an IP).
- Login is client-side-discoverable: `BeginDiscoverableLogin` builds the assertion; `ValidatePasskeyLogin` resolves the identity via the `userHandle` handler (unknown credentials rejected). Finish endpoints read the request body EXACTLY once (sessionId + credential payload share one read - the double-read produced "registration failed"/"invalid login response" on prod).
- Dashboard ownership rows: `data/shares/<ident>/<paste>.json` written at `create`/`uploadFinish` when the session cookie is present; `GET /api/shares` computes rows live from the actual paste metas and prunes gone/expired rows - zero bookkeeping. Anonymous creation records nothing.

### `GET /healthz`

Exact-match route, returns 200 `ok`. Not rate limited, no auth.

### `GET /api/paste/{id}`

- `validID(id)`: length 8–16, charset `[A-Za-z0-9_-]` only. Invalid → 404. This charset check is the **sole path-traversal defense** and gates every `filepath.Join(dir, id+".json")` - keep it.
- Missing / corrupt / expired → 404 (expired ones are deleted on sight).
- Success → 200 `{"data", "salt", "hl", "burn", "expires", "public"}` with header `Cache-Control: no-store` (`expires` = unix seconds; the read view renders it as a countdown; `public` true = plaintext lane, the client renders `data` directly with a globe glyph and never touches the fragment/unlock paths).
- **Burn semantics:** if `burn && salt == ""` → the file is deleted immediately after this read (read-then-delete; two racing readers can both succeed - accepted `ponytail:` ceiling). If `burn && salt != ""` → **do NOT delete on read**; the client issues `DELETE` after successful decryption (a link unfurler or wrong-passphrase visitor must not destroy the paste).

### `DELETE /api/paste/{id}`

Same `validID` gate. Removes the file; idempotent (nonexistent → still 200 `{"ok": true}`); other removal errors → 500.

### Static routes

- `GET /` and `GET /p/{any}` → serve embedded `web/index.html` with `Cache-Control: no-store`. Invalid id after `/p/` → 404. Any other path → 404.
- `GET /assets/{file}` → files from embedded `web/assets`; directory roots (empty path or trailing `/` after strip) → 404 (no listings); `Cache-Control: public, max-age=86400`. Note `http.StripPrefix` leaves `""` (not `"/"`) for the bare prefix - guard both. Exception for the worker: `sw.js` is served with `Service-Worker-Allowed: /` + `Cache-Control: no-cache` (it must control the whole origin from its `/assets/` path and revalidate per visit so deploys land). `.svg` and `.webmanifest` are force-mapped via `mime.AddExtensionType` (scratch containers have no `/etc/mime.types`).
- Routing uses Go ≥1.22 ServeMux method patterns (`"GET /"`, `"POST /api/paste"`). Every handler is wrapped `secure(...)`.

## 5. Server behavior mandates

- **Security headers on every response** (`secure()`): `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'self'; img-src 'self' blob:; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` - `blob:` is required so decrypted image previews / lightbox and compose chip thumbnails load; blob URLs are created by the app's own JS from ciphertext the browser decrypted (same-origin objects, no server content path).
- **No HSTS at app level** - TLS/HSTS belongs to the reverse proxy in front; the app must keep working on plain-HTTP LANs.
- **HTTP server timeouts** (slowloris): ReadHeaderTimeout 10s, ReadTimeout 30s, WriteTimeout 30s, IdleTimeout 120s.
- **Rate limiter:** in-memory fixed-window per IP. The **last** `X-Forwarded-For` entry is used when present (the single trusted reverse proxy in front appends the real client IP; spoofed earlier entries only pollute the client's own chain), else the `RemoteAddr` host. 30 per minute window; window resets by wall clock; `clear(l.hits)` on rotation.
- **Janitor:** goroutine, `time.Tick(time.Minute)`: deletes `*.burn` leftovers and any `*.json` whose `expires < now`.
- **No request logging** (privacy: never store IPs). Server log is startup + internal errors only (`log.Print(err)`), never paste content.
- **Graceful shutdown:** SIGTERM/SIGINT triggers `srv.Shutdown` with a 5s drain - in-flight creates finish before exit (`docker stop` works cleanly).
- Deliberate ceilings are marked `// ponytail:` in code; preserve the comments and the weaker-but-fine behavior they describe.

## 6. UI mandates (`web/`)

- **Bundle envelope (client framing, server-opaque):** `u32le(manifestCtLen) | manifestIv | manifestCt | file1Ct | ... | fileNCt | thumb1Ct | ...`; manifest plaintext `{note?, files: [{name, mime, size, iv, thumb?}]}` - one AES-GCM key per share (random or PBKDF2), fresh IV per blob; filenames/mime/note never reach the server. `thumb` (`{mime: image/jpeg, size, iv}`) is present for decodable images: canvas downscale (from-image orientation, max side 480, JPEG q0.72), skipped when it wouldn't beat the original's size. Thumbs append AFTER all file ciphertexts in `files` order, so file offsets stay stable and readers jump straight to a thumb at `16+mlen+Σfile.size+Σprior thumbs`. Cap ~2 GiB (in-memory encrypt ceiling, documented in the UI as a practical bound).

## 8. Verification protocol (must pass before "done")

```sh
nix develop --command sh -c 'gofmt -l . && go vet ./... && go test ./... && esbuild --bundle web/ts/app.ts --outfile=web/assets/app.js --minify --target=es2020 && tsc --noEmit && go build -trimpath -ldflags="-s -w" -o paste .'
```

- `gofmt -l` prints nothing; vet and tests must be green; `tsc --noEmit` must typecheck `web/ts/` (strict, noUncheckedIndexedAccess) - type errors are the gate the old `node --check` syntactic pass can't catch. esbuild emits the minified bundle (`web/assets/app.js`, committed artifact - regen before testing the server).
- Test suite (all in `main_test.go`, unreferenced helpers there): `TestRoundTrip` (create→read, metadata echo incl. `expires`), `TestBurnAfterRead` (2nd GET 404), `TestExpiredPaste404s` (rewinds expiry on disk: 404 + file removed), `TestBadRequests` (short data / bad ttl `2w` / `31d` / empty ttl / undecodable data / bad salt → all 400), `TestParseTTL` (valid table incl. `"10 min"`, `30 days`, `6H`; invalid `"0d"`, `"1w"`, `"1h30m"`, `"-5m"`, `"5"`, empty), `TestPassphrasePaste` (salt+burn: GET does NOT destroy, metadata echoed, `DELETE` → 200 → GET 404), `TestAssetsServed` (file 200 + dir listing 404), `TestIndexServed` (`/` and `/p/whatever` 200 with page, unknown path 404), `TestRateLimit` (30× 200 then 429), `TestPathValueAbuse` (charset/traversal/short ids → 404; DELETE same), `TestHealthz` (200 `ok`), `TestAuthGate` (with `CREATE_KEY` set: no header → 401, wrong key → 401, correct key → 200, paste publicly readable, healthz open).
- Upload suite: `TestUploadRoundTrip` (odd-sized 3-chunk init/put/finish → meta `{len,...}` no `data` → paginated range reads equal the plaintext), `TestUploadResumeOverwrite` (PUT same chunk twice: latest wins), `TestUploadFinishMissingPart` (400 + parts survive + off-size chunk rejected; retry completes; double finish idempotent), `TestUploadAbortCleans` (chunk PUT after abort → 404, second abort idempotent), `TestUploadBadRequests` (len 0/-65 above cap/bad ttl/short salt → 400; chunk index out of range/junk/negative/bad-id charset → 4xx), `TestUploadSweep` (fresh session survives; `created` older than 2h → wiped), `TestBlobBurnExpiresOnRead` (meta read flips to grace window, blob stays reachable, expired+rereaped by janitor → both gone), `TestAuthGateUpload` (init + chunk PUTs: no header/wrong key → 401, correct key → 200/204; blobs/files publicly readable AFTER they exist).
- Identity suite: `TestMeEndpoint` (anon `{name:""}`, signed-in `{name:"friend-of-tobias"}`), `TestSharesRecordAndList` (signed create records kind text row, anon records nothing, expired rows prune from listing AND ownership dir), `TestRegistrationClosed` (`REG_OPEN=false`: anon begin → 403, attach with session → options, me `open:false`). Browser-only parts (real ceremony, dashboard visuals) verify interactively or with the headless-harness screenshots.
- Public suite: `TestPublicPaste` (signed create stores plaintext verbatim incl. spaces/punct, meta echoes `public:true` + empty salt, share row carries the marker, public+burn second GET 404), `TestPublicGuards` (anon → 403, public+salt → 400, empty text → 400, >64 KiB → 400, non-base64url text accepted), `TestPublicSlug` (custom slug round-trips via `/p/<slug>`, duplicate → 409 without clobbering, short/bad-charset/long → 400, slug on encrypted paste → 400), `TestPublicUpload` (plaintext bundle through init/put/finish with slug, range reads return raw bytes, slug idempotency via tombstone, anon/salt/bad-slug guards, dup-slug 409 without clobbering), `TestPublicDisabled` (`PUBLIC_PASTES=false`: signed public create → 400, upload init → 400, gate probe `"public":false`).

## 9. Docker

- Build stage: `golang:1.26-alpine`, `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/paste .`, `COPY web/ ./web/` (embeds need it).
- Data-dir stage: `FROM alpine`, `mkdir /data && chown 65534:65534 /data`.
- Runtime: `FROM scratch`; copy binary; **`COPY --chown=65534:65534 --from=data /data /data`** - the `--chown` is required: copying an *empty* directory into scratch silently drops its ownership and non-root writes then fail with "could not store paste".
- `USER 65534:65534`, `EXPOSE 8080`, `VOLUME /data`, `ENTRYPOINT ["/paste"]`, `CMD ["-addr", ":8080", "-data", "/data"]`. Expected image size ≈ 9 MB.
- `compose.yaml`: service uses the GHCR image, `8080:8080`, named volume `paste-data:/data`, `restart: unless-stopped` - and **runs fully public as-pasted** (self-host in 30 seconds): the `environment:` block carries every knob (`CREATE_KEY`, `USER_ACCOUNTS`, `USER_REGISTRATION`, `MAX_TTL_DAYS`, `MAX_SHARES_PER_ACCOUNT`, `REG_OPEN`, `MAX_UPLOAD`, `CHUNK`) as COMMENTED lines; a deploy uncomments what it needs - never commit a real key. No TLS in compose - TLS termination is a reverse-proxy concern (document separately at deploy time); the app stays plain HTTP.
- Container smoke test: start mapped to a host port, POST a paste → 200, GET → 200, `/` → 200, `/assets/highlight.min.js` → 200.

## 10. When changing this project

Preserve, in this order: the zero-knowledge crypto contract (§2), the single-binary + single-direct-dependency posture (§1), the security headers and validation order (§4–5), `textContent` rendering (§6). Deliberate simplifications stay marked with `// ponytail:` - do not silently "fix" them into complexity. Add a test for every abuse case before adding the mitigation.
